# 模式 ① · 采集现状

> **未读本文件不许进入采集模式。**
> 适用：需要从真实系统还原「现在到底怎么跑」时。
> 不适用：手上已有基线、只是要设计下一版 —— 那种情况读 `mode-iterate.md`，本文件一行都用不上。

本模式产出**全量基线**，交给 ② 迭代模式消费。

---

## 本模式独占的硬约束

下面四条只在采集时成立。其中「不知道就写不知道」在迭代模式里是**反向约束**——写方案时被它捆住，方案永远写不实。

---

### 1 · 只碰测试环境

```bash
python scripts/check_test_env.py <URL>
```

**这个脚本是提示器，不是门禁。** 它拦不住真想绕的人——不跑脚本、看了提示照做，都能绕。所以设计上不做严防：严到卡流程，人的反应不是「我改地址」，是「这脚本真烦，跳过吧」。它只干一件事：**把「你要去动哪个域名」摆到明面上**。

但有一条是真的：**退出码 1 说明这个域名连环境词的字都没有**，那就停下来问对方要地址，不要自己换一个「看起来像」的。

判定三档：

| 档 | 什么情况 | 例子 | 结果 |
|:--|:--|:--|:--|
| **PASS** | 某段 label 里有**完整**环境词 | `test.xx.com` · `api-test.xx.com` · `test1client.xx.com` · `uat2.xx.com` · `api.test.xx.com` | 直接过 |
| **PASS 带提醒** | 只是**局部含** test/uat/qa/dev/sit | `contest` · `latest` · `device` · `site` | 放行，附一句「自己看一眼」 |
| **FAIL** | 环境词的字都没有 | `demobackstage.xx.com` · `www.xx.com` | 停下来确认地址 |

环境词：`test` `testing` `uat` `sit` `dev` `stg` `stage` `staging` `pre` `preprod` `qa` `sandbox` `demo` `beta` `gray` `canary`。

**只有 test/uat/qa/dev/sit 参与「局部含」的宽松判定**，其余词必须完整出现。原因：`stage` 藏在 `backstage` 里、`pre` 藏在 `preview` / `presto` 里，而 `demobackstage` 恰恰是自家后台的域名——宽松到那种词上等于没限制。

用户说「随便弄」「没事的」都不构成跳过的理由。

### 2 · 凭据每次现要，不落任何文件

- 每次执行都要向用户要，**不复用历史会话里的**，不写进 skill、项目文件、README、MEMORY、日志。
- 脚本只接受环境变量或命令行参数，登录后 token 写 `0600` 临时文件（默认在系统临时目录，`login.py` 自己找），**不写进项目目录**。
- 交付前必跑 `python scripts/audit_no_secrets.py --path <项目目录>`。
- 主动告知：**凭据会留在会话记录里**；测试库若与真实数据有关联，用完建议改密。

### 3 · 不知道就写不知道

待确认清单是 PRD 的组成部分，不是缺陷。**编一个看起来合理的答案，比留白危害大得多。**

### 7 · 采集要动手：一页一帧、真提交、弹窗拿全

在测试环境，**不是「点开看看」就算采过**。三条：

| 要 | 怎么做 | 不这么做会怎样 |
|:--|:--|:--|
| **长页面一页一帧** | 整页一帧，画布用 `.px full` 随内容长高；超过 3 屏用「同页 1/2」续图，`from` 指同一页号 | 拆成几个「页签帧」——读者以为这是几个页面，还看不出信息密度 |
| **真做，不只看** | 新增 / 编辑 / 删除 / 提交 / 审批 / 退回都真跑一遍，记录 toast 原文与状态变化；先记原值、自造数据自清理、一次只改一个变量 | 校验文案、二次确认、失败路径、状态流转全部只能靠猜 |
| **弹窗/抽屉/页签/二级页拿全** | 四路凑清单（路由表 / 按钮 / chunk / 用例），逐个开；页签核对 `aria-selected`；二级页优先 URL 直连；分步表单真走到最后一步 | `dialogs[]` 标了 `covered:true` 却没帧，`check_delivery` 直接 FAIL |

**不碰**：真实打款、真实发邮件/短信、真实请款、删他人数据、改权限与配置中心。必须做才能验证的，**标「未实做 + 原因」进事实清单**，不许用「应该会」写成结论。

细则（含操作纪律、记录格式、覆盖度自查）：`references/interaction.md`。

### 17 · 读代码和用例：按链路取数，报数读全，边读边收敛

三条放在一起，因为它们治的是同一个病：**读了很多，等于没读**。

#### 17.1 按链路读，不按源读

五源说的是「去哪找」，不是「怎么读」。真按源读，会读成五堆平行的信息，到整合阶段才痛苦地往一起凑。

改成按业务链路读，上下游天然能对照：

| 环节 | 只回答一个问题 | 怎么定位（**搜，别通读**） |
|:--|:--|:--|
| ① 前端触发 | 什么条件下这个表单**才能**提交 | `disabled` / `validate` / `:rules` / `watch` / 提交按钮的 disabled 绑定 |
| ② Controller | 哪些项必填、校验规则是什么 | `@NotNull` / `@Size` / `@Pattern` / `@Valid` |
| ③ Service | 走哪条分支、怎么算出来的 | `if` / `throw` / `switch` / `case` —— **不读 CRUD** |
| ④ 数据结构 | 落到哪些表、哪些字段、什么状态 | Entity / Mapper / DTO 的**字段定义**，不读 SQL |
| ⑤ 用例 | 验证了哪条规则、用了什么边界 | 全部读，但每条只取三类（见 17.2） |

**用搜定位，不用通读。** 几万行代码不需要读完，关键词能把靶点从几万行压到几百行。
均匀地读 = 该搜的地方也在硬读，结果又慢又不全。

**② 和 ④ 是最有价值的对照点。** 前端说「金额必填」，DTO 上有没有 `@NotNull`，Service 有没有兜底，用例里有没有「金额为空」的反例——四者对上才叫核过，对不上就是一条待裁定。

这张「字段 × 四层校验」的表，就是第 4 段字段约束表的原始素材。**边读边把这张表填出来**，不要读完再回忆。

#### 17.2 用例必须读全：先报数，再逐条勾

「尽可能读完」不是一个有终点的任务。读了 12 条和 47 条，它自己不知道差别，你事后也查不出来。所以要用三道锁：

1. **开工先报总数** —— 第一句就回答「用例库 这个模块下共多少条用例」。拿不出数，说明根本没去清点。
2. **一条一行落台账** —— 47 行，每行标「已读 / 并入 R-03 / 与本模块无关」，收尾统计 `47/47`。**检查一个数字，比检查几十条内容容易一百倍。**
3. **写完反查孤儿** —— 问自己「R-07 是哪几条用例验证的」。答不上来的规则，要么没读到，要么读了没穷尽。

**分批读**：10 条一批，一批一落盘。一口气灌 47 条，前面的会在上下文压缩里真的消失——不是忘了，是没了。

每条用例只取三类，其余原文丢掉：

| 取什么 | 用在哪 |
|:--|:--|
| 这条验证了哪条业务规则 | `rules[].id` 的挂载 |
| 用了什么数据（边界值、多币种、极值） | `rules[].cases` |
| 预期什么结果（含失败路径） | 第 7 段边界表 |

#### 17.3 边读边收敛：只留结论，不留原文

信息过载的根因是**读的时候存了原始形态**，到整合阶段才提炼——那时上下文已经满了，提炼不动。

每读完一段，立刻产出一条结论，原文丢掉：

```
规则：金额超过 5 万需二级审批
触发：提交时校验，取当前操作人额度
来源：PayoutService.java:213
证据：if (amt > 50000 && !hasSecondApprover())
```

100 段代码 → 30 条规则，信息量降一个数量级，还带着出处能回查。

存三层，**只有第一层进上下文**：

| 层 | 存什么 | 在哪 |
|:--|:--|:--|
| 规则清单 | 30 条一句话结论 | 上下文 / `module.json` |
| 证据索引 | 文件:行号、用例标题 | 落盘，需要时去读 |
| 原文 | 代码片段、用例全文 | **不存** |

**agent 的记忆不可靠，文件可靠。** 任何「读完要记住」的要求，都改成「读完要写下来」。
「最后整合不了」十次有八次是前面读的东西在压缩中丢了，不是它不会整合。

#### 17.4 开工前先答这五个问题

答不出任何一个，说明那个环节还没开始采集：

| # | 问题 | 答不出说明 |
|:--|:--|:--|
| 1 | 这个模块共几条用例，分别是哪几条 | 没清点 |
| 2 | 表单在什么条件下才能提交（前端触发） | 只看了截图，没读代码 |
| 3 | 哪些字段必填，前端规则和 Controller 规则一致吗 | 只读了一边 |
| 4 | 关键金额 / 数量怎么算出来的，有几条分支 | 只看了主流程 |
| 5 | 数据落到哪些表、哪些状态 | 只看界面 |

五条答完，S4 骨架确认就有底了——不用等写完 8 段才发现骨架理解错了。

## 工序：S0 → S7

> 团队同事看 `references/team-runbook.md`（纯操作卡，不解释原理）。

```
S0 环境自检 → S1 圈边界 → S2 五源采集 → S3 闸门1 事实清单
→ S4 闸门2 骨架确认 → S5 填数据 → S6 构建实拍 → S7 验收
```

### S0 · 环境自检

三件事缺一件就停：**用例库已连接**（能搜到用例库）、**代码仓库已连接**（能读后端仓库）、**测试环境三端账号**。

```bash
python scripts/check_test_env.py https://test1xxx/admin
python scripts/login.py --url <登录页> --api <网关> \
  --path /demobackstage/login/loginUser --user <账号> --out <临时目录>/prd_token.json
```

- 有验证码/短信 → 停下来让用户在自己机器上登一次，再连 `9222` 复用会话。**别硬试，会触发风控。**
- 登录失败 3 次就停。

### S1 · 圈定模块边界（决定交付范围）

用户给的是**菜单名**，要先翻译成：

1. **菜单路径**：`人员管理 → 字段配置`（写清层级）
2. **路由与页面标题**：`/personManage/fieldSetting/list`。页面 h1 可能与菜单名不一致（实测过用例叫「人员信息设置」、线上叫「人员字段配置」）
3. **依赖参数**：很多三级菜单要先选主体（客户/项目/服务方），没参数就白屏
4. **本模块内的二级页与弹窗清单** —— 最容易漏

**四个来源找，缺一会漏：**

| 来源 | 怎么找 |
|:--|:--|
| 路由表 | 前端 `umi.*.js` 里同前缀的路由 |
| 页面按钮 | 「新增 / 编辑 / 查看 / 引用模板」点了会开新页或弹窗 |
| 前端 chunk | 组件名带 `modal` / `dialog` / `drawer` |
| 用例库 | 用例里标了「弹窗」「xx 页面」的节点 |

产出是一张表：类型、入口、路由或组件名、是否本次覆盖。**没列的，后面 PRD 一定缺块。**

### S2 · 五源采集

完整通路、命令、判据见 **`references/five-sources.md`**。

| 源 | 缺了会怎样 |
|:--|:--|
| 浏览器渲染 | 布局与联动全靠猜 |
| 后端接口 | 枚举写成想象的样子 |
| 前端代码 | 漏掉界面看不见的分支 |
| 后端代码 | 权限映射、状态置位、跨模块副作用只能从界面倒推，倒推经常错 |
| 用例库 | 漏业务规则，且不知道哪些是旧版 |

一条规矩：**「能访问」不等于「核对过」。** 台账里只记真看到的位置；拿不到标 `部分`/`未核` 并写明原因。

**怎么读，见硬约束 17。** 上面这张表回答的是「去哪找」，不是「怎么读」——按源读会读成五堆平行信息，按链路读才能上下游对照。读代码用搜不用通读，读用例先报数再逐条勾，读完立刻收敛成结论、原文丢掉。

### S2.5 · 实拍页面骨架（原型图的唯一合法来源）

原型图不许照着记忆画。**先实拍，再生成**：

```bash
# 起一个带调试端口的浏览器。--headed 不能省：新 profile 里没有登录态，
# 要你在弹出的窗口里亲手登录一次测试环境（脚本不碰凭据）
python scripts/launch_chrome.py --headed

# 抓主页面 + 点开弹窗各一帧，输出 snapshot/<key>.json 与实拍截图
python scripts/snapshot_page.py \
    --base https://test1x.example.com \
    --url /personManage/fieldSetting/list --key ops-field --page p1 --name 字段配置列表

# 弹窗：--open 给按钮文案；批量就写 plan.json（见脚本头）
python scripts/snapshot_page.py --base https://test1x.example.com \
    --url /personManage/fieldSetting/list --key ops-field --page p2 \
    --name 管理分组 --open 管理分组
```

抓完会打印每帧抽到了什么：

```
[1/1] p1  /personManage/fieldSetting/list
        → 6 张表 / 48 列、8 个按钮
```

**「什么都没抽到」的那帧不能用**——登录失效或页面没加载完，重抓。

抽到的东西：标题 / 描述 / 面包屑 / 页签 / 顶栏菜单 / 侧栏菜单（含层级）/
表单分组与字段（类型、必填、选项、占位符）/ 表格（列、首几行、状态标签）/ 按钮 / 分页 / 实拍截图。

> 按钮点了没反应？有些按钮要先用真鼠标事件才触发。脚本已经走 `Input.dispatchMouseEvent`；
> 仍打不开就换一个按钮，或直接用路由抓二级页。

**三个必须做到的采集动作**（细则 `references/interaction.md`）：

1. **长页面一页一帧**：`proto_from_snapshot.py` 会按正文分块数自动判长页，用 `.px full` 让画布随内容长高；
   超过 3 屏才分两段，标题写「同页 1/2」、`from` 指同一页号。**不许把一页拆成几个页签帧。**
2. **真提交，不只看**：能新增/改/删/提交/审批就真跑一遍，把提示文案照抄下来；不可逆动作不做，标「未实做 + 原因」。
3. **弹窗/抽屉/页签/二级页拿全**：`--open` 开弹窗、`--tab` 切页签（会核对 `aria-selected`）；
   分步表单真走到最后一步。拿不到的标 `covered:false` 并挂 `ask`，**不许用「其他类似」带过**。

### S3 · 闸门 1 · 事实清单（层 1 过程门）

```bash
python scripts/build_facts.py --data facts.json --out 事实清单.html
# 对方逐条回完之后，把「谁、什么时候、裁定了几条」记下来——这是门禁，不是备注
python scripts/gate.py facts --root . --module <key> --by <对方姓名> --total 12 --answered 12
```

- 每条必须有：`id / cls / sev / area / title / old / new / src / proof / note / ask`
- `cls`：`fix` 需改 / `add` 缺失 / `conflict` 冲突 / `risk` 风险 / `ask` 待确认 / `ok` 一致
- **冲突未裁定前不许进正文**，只能出现在待确认里
- **这一步不通过，不要动手写 PRD。** 用户按编号回即可。
- `--total` 与 `--answered` 不等时 `gate.py` 直接拒——还有没答的，不叫「已裁定」

**这份台账就是 PRD 第四块（核查）的唯一数据源**，别在 `module.json` 里另写一份。
S6 构建时加 `--facts` 会自动同步进去并回写模块数据。

### S4 · 闸门 2 · 骨架确认（层 1 过程门）

事实清单过了之后，把要写进正文的骨架单独列一遍确认：业务目标一句话、主流程几步、状态机几个态几条迁移、规则条数与编号区间、哪些内容**不写**。

避免写完 8 段才发现骨架理解错了。确认完留痕：

```bash
python scripts/gate.py scope --root . --module <key> --by <姓名> \
  --what "8 段 / 22 条规则 / 7 态 9 条迁移 / 不写供应商单据与自营单据"
```

`--what` 必须写具体数字。只写「已确认」等于没确认——三个月后没人知道当时确认的范围。

### S5 · 填数据

写 `modules/<key>.json`。逐段要求、AI 层结构、写作纪律见 **`references/doc-8sections.md`**，完整样例 `assets/example_module.json`，原型组件见 **`references/prototype-kit.md`**。

**这个文件要装四块，一块都不能空**——出来的 HTML 顶栏就是靠这四块切的：

| 块 | 字段 | 硬要求 |
|:--|:--|:--|
| ① 原型 | `prototype.frames[]` | **用 `proto_from_snapshot.py` 从快照生成**，别手写；主页面固定 P1；**每个 `covered:true` 的弹窗/二级页各占一帧**；只准用 `px-` 组件 class，**不许写 `style=`**（契约会拒）；每帧带 `from: "<快照>.json#p1"` |
| ② 叙事 | `sections[]` + `rules[]` + `transitions` | 8 段固定；第 5、6 段 `html` 留空，由数据渲染 |
| ③ AI 读 | `context` / `entities` / `layout` | 枚举列全；`context` 要写清哪种优化是错的 |
| ④ 核查 | `facts[]` | **别手写**，S6 用 `--facts` 从台账同步 |

三条铁律：

1. **表是真相，图是表的渲染。** 状态机先写迁移表（含 `from/to/trigger/guard/api`），图由表生成。反过来做，图会漏迁移。
2. **case 挂在规则下，不混在散文里。** 每条规则配 `给定/当/则`，分正例、反例、边界。混在段落里的举例会被下游当成新规则。
3. **每条规则挂 `facts`。** 写 `"facts": ["F-01","F-07"]`，指向台账里真实存在的编号。挂了叙事里才出「依据 F-01」的可点链接，读者能一跳看到这条结论是哪个源给的。不挂就是 FAIL。

**口径被纠正时，别只改他指到的那句。** 一条口径散在六个地方（正文 / `context` / 边界表 / 规则与 case / 原型上的字 / 待确认），
只改一处，下一轮会在别处再被问一遍。用 `scan_wording.py --term "旧=新"` 把旧说法扫干净：

```bash
python scripts/scan_wording.py --path modules/<key>.json --term "旧说法=新说法"
```

细则见 `references/writing.md` 第六节。

### S6 · 构建 + 实拍

```bash
# --facts 把台账同步进第四块，并回写 modules/<key>.json（只有一个事实源）
python scripts/build_module_prd.py --data modules/<key>.json \
  --facts facts/<key>.facts.json --out out/<key>.html --strict
python scripts/shot_verify.py --html out/<key>.html
```

产物打开后**顶栏五个页签每个都要看过**：原型+文档 / 纯原型 / 测试用例 / 代码逻辑 / 核查。

- 「原型+文档」那栏要确认每一帧都真有内容，不是骨架的「待画原型」提示
- 「纯原型」是投屏和评审用的满屏模式，要确认图和粉色改动标注在放大后仍然可辨
- 没有原型帧的模块，原型栏显示一块虚线空态——那是正常的，不是渲染坏了
- **底部按钮被切掉一半**这类问题脚本会报：`shot_verify` 会逐帧点一遍，量每个 `overflow:hidden` 盒子的内容有没有溢出，输出「逐帧裁切：P5字段详情 → px 竖向溢 186px」。看到这条别当噪音，先查那一帧。

- **结构校验只能证伪语法，证不出视觉。** 必须实拍：文字重叠、标签压线、表格挤成多行、标注孤悬——HTMLParser 一个都查不出来。
- 截图脚本不再用固定 sleep：会等字体、图片、连续两帧布局都不再变才按快门。定长等待要么截早（半截渲染），要么白等。
- 无头 Chrome 启动方式（沙箱里唯一能跑通的组合）见 `references/five-sources.md` 第五节。

### S7 · 验收（层 2 交付门）

```bash
python scripts/gate.py doc    --root <工作台> --by <姓名> --note "整份看过"   # 文档级确认（默认）
python scripts/gate.py status --root <工作台> --module <key>                    # 单模块四道门
python scripts/check_delivery.py --root <工作台> --module <key> --strict
```

**`--strict` 才把「反查」与「签字」按未通过算**——日常改稿不必被签字卡住，交付必须过。

查七类，前五类是机器自证，后两类是「门禁上的门禁」：

| 组 | 查什么 | 谁在把 |
|:--|:--|:--|
| 流程 | 闸门 1 裁定、闸门 2 骨架、待确认清空 | 人（有署名） |
| 数据 | 契约、TODO、示例占位、引擎版本、五源 | 机器 |
| 内容 | 原型帧、8 段、规则挂依据、弹窗数量、实拍快照 | 机器 |
| 产物 | HTML 新鲜度、页内数据与 json 逐字节一致、无外链 | 机器 |
| 命名 / 措辞 | V 稿次、角色词、量词、旧口径残留 | 机器 |
| **反查** | 规则都在产物里、P0 事实被引用、答案不是空话、弹窗对得上帧 | **机器反着查** |
| **签字** | 封板（一个人签）：整份 `doc` 或逐个 `sign`，且封的是当前内容 | **人（产品经理本人）** |

**全绿才算交付。** 合并成全量前还要过合并门：`merge_modules.py` 默认拒绝没封过板的模块。
为什么要有两层、每层拦得住什么，见 `references/gates.md`。

## 团队协作（用法 C）

### 初始化

```bash
python scripts/init_run.py --root ./prd-run --project "项目名" \
  --module "管理后台|人员管理 / 人员字段配置|ops-person-field|张三" \
  --module "管理后台|客户中心 / 客户列表|ops-customer|李四"
```

产出：

```
prd-run/
├── run.json                 项目级登记：引擎版本、模块分配
├── origin.json              来源身份证（建台时立骨架版，出全量才换成正式版）
├── 怎么干活.md               操作卡（自动复制 team-runbook.md）
├── modules/<key>.json       ← 唯一要人工填的文件（骨架已搭好，含 TODO 标记）
├── facts/<key>.facts.json   ← 五源事实台账（闸门 1 留痕）
└── out/<key>.html           ← 构建产物，不许手改
```

### 分工规矩

- **一个三级菜单 = 一个模块 = 一个 key = 一个人**。不要让两个人碰同一个 json。
- **复制工作台要整目录复制**，别只拷 `modules/`——`origin.json` 在根目录，它是合并时证明「这份副本基于哪一版」的唯一凭据。漏了它，合并前就只能靠推断。
- `key` 全局唯一，命名 `{系统简写}-{模块简称}`，如 `ops-person-field`。**定了不许改**（合并靠它去重排序）。
- 模块之间**有依赖的**（如「客户隐藏字段」影响 7 个页面），在 `context.yaml` 里写清跨模块影响，不要各自实现一遍。

### 看谁交了

```bash
python scripts/init_run.py --root ./prd-run --list
```

### 收齐后合并

```bash
python scripts/check_delivery.py --root ./prd-run --all      # 先全员验收

python scripts/merge_modules.py --root ./prd-run \
  --out 全量PRD.html --md 全量PRD.md --json 全量PRD.json --strict
```

产出三份：

| 文件 | 给谁 | 说明 |
|:--|:--|:--|
| `全量PRD.html` | 人 | 左导航切换模块 + 总览页（模块索引 / 待确认汇总 / 缺口 / 五源覆盖） |
| `全量PRD.md` | AI 检索 | 纯文本层，段落顺序与 8 段一致 |
| `全量PRD.json` | AI 生成 | 合并后的结构化数据，直接喂给模型生成任何形态 |

同事只交了 HTML 也能兜底合并（从页内 `window.PRD_DATA` 恢复）：

```bash
python scripts/merge_modules.py --from-html a.html b.html --out 全量PRD.html
```

**引擎版本不一致时默认拒绝合并**——混版本会缺字段。除非加 `--allow-mixed` 强行合并。
