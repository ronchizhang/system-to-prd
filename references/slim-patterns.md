# 删留清单、改写句式与技术坑

`slimming.md` 讲流程，本文讲每一句怎么落刀，以及动数据时会踩的坑。

---

## 一、留（一个字都不能少）

这五类看着像废话，实际是研发照着写代码的依据。删了就是删规格。

| 类别 | 长什么样 | 为什么必须留 |
|:--|:--|:--|
| 字段值域与异常 | 「≤2 平铺；>2 前 2 +『+N』；导出不截断」 | 边界条件，测试照着测 |
| 谁能改 / 谁不能改 | 「人一个都不能改；回执未到保持『打款中』」 | 权限与状态归属 |
| 防错硬约束 | 「回执出现未知状态，置『支付中』+『状态待确认』，绝不默认成功」 | 删了就会写错账 |
| 判定条件与优先级 | 「两条件同时成立：类型=兼职讲师结算申请 且 账户=通道C」 | 单条件判定会漏付 |
| 数值真值与来源 | 「20 USD/笔（见 R-DEMO-WDR-10），非通道成本 3–5 USD」 | 三个数别混 |

**判断方法**：这句话能不能变成一条测试用例？能 → 留。只能变成一段背景介绍 → 删。

## 二、删（七类，按出现频率排）

### 1. 改稿过程记录

> 2026-11-03 15:05 修正（F-22、F-03）：① 配置页不用「展开说明」按钮，第 10 行行名左侧一个三角…② 「银行卡结算币种」本来就是多选，本期没有改动这个控件…

这是写给内审看的，读者不需要知道上一稿怎么写的。**处理**：如果仍有未裁口径，压成一行进「已定口径」表；已进正文的直接删。

### 2. 设计动机

> 把人的角色从记账员换成发令员。

> 先有汇总表，才有支付推荐。

读者要的是「怎么算」，不是「为什么这么想」。**处理**：删。真要留理由，单独出一份《设计决策记录》。

### 3. 自我辩解与代价声明

> 代价写在这里（取舍，非遗漏）：极端情况下…

**处理**：把事实留下（「重试可能重复付款」），把辩解删掉。

### 4. 文档元信息

> 本文是改造需求，不是现状说明书；对照基线为测试环境上线的现状版本。

> 挂在第 7 段末，因为第 8 段是待确认、只能往后接。

**处理**：删。

### 5. 重复示例

5 个模块各有一张「典型场景」表，而用例栏已经有 201 条用例。

**处理**：删表，留一句「场景取值见本模块用例栏」。

### 6. 口语比喻与修辞

> 兼职讲师提现的**流水账**。

> 它不是待办池，没人在这里批单。

**处理**：换成事实陈述。「不是待办池」→ 直接说「审批在 X 页，付款在 Y 页」。

### 7. 与上文重复的行

> 用来做什么：事后追溯。资金出了问题，用这一页查这笔钱当时是怎么走的。

上一行「是什么」已经说了这是提现记录清单。**处理**：删。

## 三、改表格：砍列的四个方向

一张表超过 4 列，每格只能写半句，读者反而更累。按这个顺序砍：

| 砍什么 | 判据 | 实例 |
|:--|:--|:--|
| 控件列 | 值域能反推（「只读标签」从「人不可改」能看出来） | 6 列字段表 → 4 列 |
| 论证列（「为什么」） | 答的是动机不是规格 | 「谁做 / **为什么**」整列删 |
| 示例列 | 用例栏里已经有了 | 「本次示例（兼职讲师结算申请打款）」列 |
| 可合并列 | 两列答同一件事 | 「越界 / 异常处理」并进「值域」，用「；」分隔 |

砍完还宽就**拆表**（一张按字段、一张按异常），不要硬压。

**行内合并**：表头有 `#` 和「步骤」两列时，把序号并进步骤列，写成「**1** 筛单」，省一列。

## 四、改写句式

### ① 删「不是 A 而是 B」

这种句式的三宗罪：立假靶子（读者没有这个误解）、同义替换（A=B）、无关硬凑。

| 旧 | 新 |
|:--|:--|
| 打款状态**不是**这张单自己维护的，**是**打款工作台回写过来的 | 由打款工作台逐笔回写 |
| 结算信息可能**不是**单值 | 可能多值 |
| 一行出现多币种是正常形态，**不是**数据错乱 | 属正常形态 |
| **而不是**现在就为它加一套状态机 | 现阶段不为它加状态机 |

例外：真的有人会搞错 A，且 A≠B，那就留。判据：**先问有没有人真的会做 A 判断**。

### ② 名词短语代替整句

> 旧：兼职讲师在学员端点「提现」，这里就多一条记录。一次提现一条，不会合并、不会覆盖。
> 新：提现生成一条，一笔一条，不合并、不覆盖。

### ③ 长散文改两列表

散文里出现「有 A、有 B、还有 C」「第一…第二…」，一律转 `项 | 内容` 两列表。

### ④ 论证表整表删

| 这条线上有什么 | 谁做 | 为什么 |
|:--|:--|:--|
| 发起打款、分批发送 | 系统 | 主正向。人站在这里，成本随机构数线性增长 |

「为什么」列是动机，整表删；如果「谁做」这条信息在别处没有，留一句：「主正向流程系统跑完，人工只碰逆向与分支。」

### ⑤ 术语先定义再生效

表格或段落里出现一个读者可能不认识的字段名，在第一次用到它的表里加一行「指的是」放首行，先说清取值，再说规则。别让读者读到第三条规则才回头查这个词是什么。

## 五、表格模板（直接抄）

**窄表（2 列）——情形 / 处理**

```html
<div class="tw"><table>
<tr><th style="width:24%">情形</th><th>怎么处理</th></tr>
<tr><td>某协议必填字段为空</td><td>标「缺失」，<b>仍参与发起</b>，由通道单笔驳回</td></tr>
</table></div>
```

**中表（3 列）——情形 / 行为 / 禁止**

```html
<tr><th style="width:22%">情形</th><th>系统行为</th><th style="width:32%">禁止做法</th></tr>
```

**改前改后（3 列）**

```html
<tr><th style="width:20%">位置</th><th style="width:30%">改前</th><th>改后</th></tr>
```

**字段表（4 列）**

```html
<tr><th style="width:17%">字段</th><th>值域 / 异常</th><th style="width:14%">谁写</th><th style="width:11%">变化</th></tr>
```

- 「本次变化」只留编号（C11），不留描述
- **列宽一律用百分比，不用 px。** px 在窄栏会把最后一列压成一字一行（见第六节第 4 条）

## 六、技术坑

全部踩过。第 1–3、11–13 条是数据层的，第 4–6 条与 `css-pitfalls.md` 有重叠，这里只留与瘦身直接相关的部分。

### 1. 不要手改 HTML 正文

正文在 `window.PRD_DATA` 里（一个几十万字的 JSON）。改 HTML 里的渲染结果刷新就没了；直接改 JSON 字符串容易少一个引号，整页白屏。

**正确顺序**：拆 JSON → 改 JSON → 注回。

```bash
python3 scripts/inject_prd.py 源.html 改好的模块目录 输出.html
```

### 2. 提取 JSON 要括号配对，不能用正则

JSON 正文里有大量 `{` `}` `"`，`re.search(r'\{.*\}')` 一定切错。`split_prd.py` / `inject_prd.py` 已实现配对扫描，直接复用，不要自己写正则。

### 3. 删「人工写的 callout」会连带丢交叉引用

一个 `<div class="callout">` 里可能塞了 6–8 个 `<a class="xref" data-xa="F-xx">`。删块看着只是删了一段话，实际把引用删了，`verify_slim.py` 会报丢引用。

**处理**：删块前先 `grep data-xa`，把里面的引用收进一张「已定口径」表（每行带引用），这样引用还在，内容也压了。

### 4. 表格列宽写 px 会在窄栏压成竖排

「本模块包含的页面与弹窗」那张表 5 个 `th` 写死 `76px / 180px / 200px / 60px`，右侧窄栏里总宽超过容器，最后一列被压成一字一行。**改百分比**：`11% / 20% / 30% / 9%`。

这类列宽由 JS 生成（`dialogTable()`），源码是跨行拼接的：

```js
'<th style="width:76px">类型</th><th style="width:180px">名称</th>'
    + '<th style="width:200px">入口</th>...'
```

所以不能整串替换，要逐个 `width:76px">类型` 这样换。原理见 `css-pitfalls.md` 第 1 条。

### 5. 结构校验查不出视觉错误

`verify_slim.py` 全绿只代表骨架没坏。**砍完列必须截图**，至少截改动最大的那个模块。

### 6. 截模块页的方法

模板底部是 `renderNav(""); showOverview();`。把 `showOverview();` 换成 `goto(4);`（4 是模块下标），截出来就是该模块首屏。

**不要用** `setTimeout` 去点导航按钮——脚本不在全局作用域，`goto` 未定义；`--screenshot` 也不等定时器。

```bash
sed 's/showOverview();/goto(4);/' 文档.html > /tmp/shot.html
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new \
  --virtual-time-budget=15000 --window-size=1500,3400 \
  --screenshot=/tmp/m.png "file:///tmp/shot.html"
```

长页用 `--window-size=1500,9000` 一次抓完，再用 PIL 裁剪看局部。

### 7. Python 脚本里写 HTML 模板，别用 `%` 格式化

CSS 的 `width:17%` 会和 `%(KEY)s` 打架，报 `unsupported format character '"'`。

**用占位符自替换**：模板里写 `@@F37@@`，最后

```python
for k, v in MAP.items():
    NEW = NEW.replace('@@' + k + '@@', v)
assert '@@' not in NEW
```

### 8. glob 要排除备份

```python
if '.orig' in p or '.bak' in p: continue
```

否则 `.bak.json` 会被当成模块注进去，两版混在一起。

### 9. 重新注入会覆盖 overview

注入脚本带「顺便覆盖 meta / overview」逻辑时，第二次跑会把第一次的手工修正覆盖掉。**改 overview 要单独存一个文件，并在注入前确认它是最新版**，且必须从改后稿提取，不是原稿。

### 10. 中文标点替换只对文本节点做

要批量换引号、破折号，先按标签切：

```python
parts = re.split(r'(<[^>]+>)', html)
# 只对 parts 里不以 < 开头的做替换
```

整段跑正则会改坏 `class="..."` 里的引号。

### 11. 校验要比对「多重集」不是「集合」

dchg 用 `sorted()` 后比，因为一个改动点左右各出现一次（`div` + `span` 都带 `data-chg`），数量必须一致。用 `set` 比会漏掉「删了一半」的情况。

xref 反而应该用集合比——同一个引用在正文里出现几次不固定，只要不丢就行。

### 12. 在 raw HTML 上做字符串替换，改不到 JSON 里的内容

JSON 里的引号是转义的：文件里看到的是 `data-chg=\"C15\"`。所以在整份 HTML 字符串上 `replace('data-chg="C15"', ...)` **匹配不到正文**，可能只改到 JSON 之外的边角（原型片段、脚本常量），然后你以为改动生效了，实际没有。

**正确做法**：解析 → 改对象 → 序列化 → 拼回。

同样是这个原因，做「破坏性测试」验证 `verify_slim.py` 是否真能抓错时，也必须走这条路——直接在 raw HTML 上删东西，删的往往是边角料，测出来「通过」是假象。

### 13. `split_prd.py --with-overview` 会把「原稿概览」带回去

它导出的是**原稿**的概览。如果先改了概览又用这份 `_overview.json` 注入，等于把改好的概览覆盖回原稿——而且 `verify_slim.py` 不查概览，看不出来。

**判据**：注入前看目标文件的概览字数有没有跳回原值。
