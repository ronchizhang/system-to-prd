# 原型怎么写：先实拍，再生成，不手写

## 详情页不要手画，让脚本按坐标还原

列表页可以照着组件拼；**详情页必须用脚本生成**，因为详情页的排版是「谁在谁上面、谁在谁右边」，
手画必错位、必漏块。`snapshot_page.py` 抓的是每个文字块的
`(x, y, 宽度, 字号, 字重, 是否带灰框, 单选选中/禁用)`，
`proto_from_snapshot.py` 按坐标还原成有序块再渲染：

| 真实页面里的东西 | 还原成什么 | 判据 |
|:--|:--|:--|
| 分块标题 | 卡片头 | 字号 ≥16、加粗、贴着内容左边界 |
| 块内小标题 | 带框子卡片 | 字号 14、加粗（如发起人信息 / 流程状态信息） |
| 左右两栏 | `px-cols` + 列宽比例 | 同一行出现两个小标题且 x 差 >300 |
| 标签：值 同一行 | `px-kvi.inl` | 两者 x 间距 <220 |
| 标签在上、值在下 | `px-kvi` | 标签行 + 下一行值，按 x 区间配对 |
| 值带灰底框 | `px-vbox` | 元素或父级有底色/边框 |
| 统计数字 | `px-stats` | 一行里连排「标签：数字」≥3 组 |
| 单选（打款方式） | `px-segi.on/.dis` | 抓 `radio-wrapper-checked` / `-disabled` |
| 页面右下角按钮（流程干预） | 页脚操作条 | 祖先里有 `footer` 或 fixed/sticky |
| 上传区 | `px-upload` | 「N / M」+ 上传文件按钮 |

**顺序只由 y 决定。** 分块、表格、统计、上传是按 y 交错排的，不是「先所有分块、再所有表格」——
后者会把「结算信息」排到费用明细前面，图就废了。


单页 PRD 的第一块是**原型图**。它和叙事、AI 读、核查同在一个 HTML 里，靠顶栏切。

原型不是截图，是**用固定组件拼出来的 HTML 片段**。原因很简单：十个人截图，十种分辨率、十种缩放、十套字体；合并成全量 PRD 后排版会散。用固定组件，谁来画都长一个样。

**但它也不是「照着印象画」。** 结构必须来自真实 DOM —— 几列、哪些字段、什么按钮、什么状态，全部实拍取得。手写必然漏，漏的那几列没人看得出来。

## 零、两步走，不要手写

```bash
# ① 实拍：真实页面 → 结构化快照（自动带截图）
python scripts/snapshot_page.py --base https://test1x.example.com \
    --url /a/b --key ops-x --page p1 --name 列表
#    → snapshot/ops-x.json + snapshot/shots/ops-x-p1.png

# ② 生成：快照 → px- 原型帧，直接写进模块数据
python scripts/proto_from_snapshot.py --snapshot snapshot/ops-x.json \
    --data modules/ops-x.json --write
#    → prototype.frames 里出现 P1，带 from: "ops-x.json#p1"
```

生成出来的帧会写着 `from`，验收会拿它去查快照文件在不在、页号对不对。**填了假 from 会被拦。**

| 情况 | 怎么做 |
|:--|:--|
| 弹窗 / 抽屉 | `--open "按钮文案"`，脚本用真鼠标点开再抓 |
| 页签内的内容 | `--tab "页签名"` |
| 一次抓多帧 | 写 `plan.json`，见 `snapshot_page.py` 头部的例子 |
| 抓不到（白屏、登录过期） | 重抓；还不行就标 `部分`，别硬编 |
| 生成得不好看 | 手改 `html` 可以，但**改完要保留 `from`**，否则等于凭印象画 |

生成器只做「结构转写」：真实 8 列就 8 列，真实有「可填写 / 隐藏」就上标签。它不会替你编不存在的字段 —— 这是设计如此。

## 一、一帧画什么

```json
"prototype": {
  "viewport": "1440x900",
  "note": "这一组帧统一要交代的事",
  "frames": [
    {"id": "P1", "name": "列表", "state": "默认态", "route": "/x/y",
     "note": "这一帧专属的说明", "html": "<div class=\"px\">…</div>"}
  ]
}
```

| 规则 | 为什么 |
|:--|:--|
| **P1 一定是主页面** | 读者从主页面开始看，页签按 P1、P2… 排 |
| **每个已覆盖的弹窗 / 二级页各占一帧** | 清单里 `dialogs[].covered=true` 的，都得有帧。少画一帧，验收会提醒 |
| **一帧一个状态** | 默认态 / 空态 / 校验失败 / 弹窗打开，不要在一张图里塞两种状态 |
| `note` 必须写 | 看图的人不知道哪些是示例数据、哪里被裁掉了，就会问 |
| `viewport` 用 `1440x900` | 后台统一。手机端用 `390x844` |

帧数参考：一个三级菜单模块通常 3-6 帧（主页面 1 + 新增/编辑 2 + 关键弹窗 1-2）。

### 帧类型：`kind`

`kind` 是可选字段，缺省按 `ui` 处理——老数据不用补。

| kind | 是什么 | 要不要 `from` | 受「只写界面真有的字」约束吗 |
|:--|:--|:--|:--|
| `ui` | 实拍界面（默认） | 要 | 要 |
| `flow` | 流程 / 判定逻辑（SVG） | 不要 | 不要 |
| `diagram` | 全景 / 分层图 | 不要 | 不要 |
| `explain` | 界面化说明页（要上线的页） | 不要 | 不要 |

后三类是**生成图**：`check_delivery` 的「帧上没有 from」「图上没有说明条」只针对 `ui` 帧，生成图里有说明文字是它的本分。

什么时候该画、画成什么形式、图里的节点怎么写，见 SKILL.md 硬约束 17。

```json
{"id": "P0", "kind": "diagram", "name": "原理图 · 评审讲解首页", "html": "<div class=\"px\">…</div>"}
```

## 二、骨架：每个 `.px` 都是整屏

```html
<div class="px">
  <div class="px-top">
    <div class="px-logo">Demo <i>Brand</i></div>
    <div class="px-tmenu"><span>机构</span><span class="on">学员</span></div>
    <div class="px-tright"><span>机构名</span><div class="px-av">运</div></div>
  </div>
  <div class="px-body">
    <div class="px-side">
      <div class="px-mi on">学员管理</div>
      <div class="px-mi sub on">学员档案字段</div>
    </div>
    <div class="px-main">
      <div class="px-crumb">学员管理 <i>/</i> 学员档案字段</div>
      <div class="px-h1">学员档案字段</div>
      …内容…
    </div>
  </div>
</div>
```

`.px` 自带 1440 宽、浅灰底、纵向 flex。**不要给它加宽度**，引擎会按容器宽度等比缩放。

## 三、组件清单

### 容器与布局

| class | 长什么样 | 说明 |
|:--|:--|:--|
| `.px-top` | 深蓝顶栏 52px | 里放 `.px-logo` `.px-tmenu` `.px-tright` |
| `.px-tmenu span` | 顶栏菜单项 | 加 `.on` 高亮 |
| `.px-side` | 左侧 196px 菜单 | 里放 `.px-mi`，二级用 `.px-mi.sub` |
| `.px-main` | 内容区，自带 16/20 padding | 里面按顺序放 crumb → h1 → toolbar → card |
| `.px-crumb` | 面包屑 | `<i>/</i>` 做分隔符 |
| `.px-h1` | 页面标题 18px | 后面可以跟 `.px-tag` |
| `.px-card` | 白卡 | 配 `.px-card-hd` + `.px-card-bd` |
| `.px-tabs` / `.px-tab` | 页签 | `.px-tab.on` 高亮 |
| `.px-empty` | 空态占位 | 说「此处省略」也用它 |

### 工具条与按钮

| class | 说明 |
|:--|:--|
| `.px-toolbar` | 一行搜索 + 筛选 + 按钮，`.sp` 撑开中间 |
| `.px-in` | 输入框；加 `.ph` 显示占位色 |
| `.px-sel` | 下拉框，自带 ▾ |
| `.px-btn` | 次按钮 |
| `.px-btn.pri` | 主按钮（蓝底） |
| `.px-btn.danger` | 危险（红字） |
| `.px-btn.sm` | 小号 |
| `.px-btn.link` | 文字按钮（表格操作列）；`.link.d` 是红色 |

### 表格

```html
<table class="px-table">
  <tr><th class="w-l">字段名称</th><th class="w-m">字段类型</th><th class="w-s">状态</th></tr>
  <tr><td>姓名</td><td><span class="px-tag">文本</span></td>
      <td><span class="px-tag green">启用</span></td></tr>
</table>
```

列宽只用 `.w-s`(84) / `.w-m`(132) / `.w-l`(24%) / `.w-xl`(30%)，**不许写 `style="width:…"`**。

### 标签、开关、勾选、分页

| class | 说明 |
|:--|:--|
| `.px-tag` | 灰标签；`.blue` `.green` `.red` `.amber` 四个语义色 |
| `.px-sw` | 开关；`.on` 打开 |
| `.px-chk` | 勾选框；`.on` 勾上 |
| `.px-pager` | 分页条，`<b class="on">` 是当前页 |

### 表单（3 列栅格）

```html
<div class="px-form">
  <div class="px-frow"><div class="px-flabel"><em>*</em>字段名称</div>
    <div class="px-fctrl ph">请输入</div></div>
  <div class="px-frow full">…整行…</div>
</div>
```

- 一行 3 列；`.px-frow.full` 占整行（末项通常整行）
- 弹窗里用 `<div class="px-form c2">` 变 2 列
- 必填星号用 `<em>*</em>`
- 下拉用 `.px-fctrl.sel`；多行文本用 `.px-fctrl.area`
- 字段下方说明用 `.px-fhint`

### 弹窗与抽屉

```html
<div class="px-mask">
  <div class="px-modal wide">
    <div class="px-modal-hd">新增字段 <span class="px-tag blue">第 1 步 / 共 2 步</span>
      <span class="x">✕</span></div>
    <div class="px-modal-bd">…</div>
    <div class="px-modal-ft"><button class="px-btn">取消</button>
      <button class="px-btn pri">确定</button></div>
  </div>
</div>
```

`.px-mask` 直接放在 `.px` 的最后（不是放在 `.px-main` 里），否则遮罩只盖住内容区。
`.px-modal` 默认 560 宽，表单用 `.wide` 720。

抽屉：`.px-drawer` 固定在右侧 520px，配 `.px-drawer-hd/bd/ft`。

## 四、禁止项

| 不许 | 改成 |
|:--|:--|
| `style="…"` | 用组件 class；缺 class 就提给引擎维护者，别自己加 |
| `<script>` | 原型是静态的，交互靠多帧表达 |
| 外链图片 | 需要图标用文字或 `.px-tag` |
| 真实机构姓名、手机号、证件号 | 用「示例校区A」「138****0000」这类脱敏示例 |
| 一个帧塞两种状态 | 拆成两帧 |

契约校验会拒 `style=`，报错信息是「%s 里写了内联 style」。

## 五、自检

```bash
python build_module_prd.py --data modules/<key>.json --out out/<key>.html
```

然后打开 HTML，点顶栏「原型」：

- 缩放到 100% 时，界面元素不重叠、文字不溢出
- 每个弹窗 / 二级页都能在页签里找到
- 底部 `note` 说清了这张图的可信边界

> 实拍确认：`python shot_verify.py --html out/<key>.html`，会逐视图截图并量出缩放比、帧数、横向溢出。

## 四、原型上的每个数字，都要在后端找得到出处

画原型时最容易犯的错，不是画错组件，是**画出后端根本不存在的值**。

真实案例：打款二次确认弹窗上写了「发送批次 **2 批**（本地 · 通道FA / 通道S）」。
全库搜 `xpay + payout` 只有两个 DTO 字段，**没有任何打款调用代码** —— 批次这个概念在后端不存在。
图上线了，开发照着做，等于让他去实现一个我凭空造出来的字段。

**规矩**：

1. 凡是「看起来像系统算出来的」数字（批次、合计、百分比、状态计数），先在代码里找到它怎么来的；
2. 找不到就两条路：**标成设计**（在 note 里写「本稿定义，后端尚未实现」），或者**换成算得出来的口径**；
3. 千万别让它默认看起来像现状 —— 读者不会去分辨哪个数字是设计、哪个是实算。

自查：逐个数字问一句「这个值是哪个接口/哪张表返回的」。答不上来就标。

## 五、模板已经提供的能力（别重复写内联样式）

`assets/module_prd.html` 里这些类是通用的，直接用：

| 类 / 属性 | 用途 |
|:--|:--|
| `.px-ellip` | 长文本单行截断 + 省略号（配 `title` 悬停看全名）。**一段太长用它** |
| `td.wrap` | 允许单元格换行。**只用于「一条里有多段」**（金额、学员名单），不是给长文本用的 |
| `th.w-l` / `th.w-n` / `th.w-m` / `th.w-dt` | 列宽：24% / 178px / 216px / 104px。7 列列表用 `w-l` + `w-dt` + `w-m` 最稳 |
| `.px-tags` / `.px-tag` / `.px-more` | 多值字段：平铺 + `+N` |
| `.px-tips` + `.px-tip` | 悬停浮层（表格里也能用，`td:has(.px-tips)` 已放开 overflow） |
| `.px-chg` / `.px-chg-bd` / `chg-col` / `chg-flag` | 改动标注：块级 / 列级 / 表头徽标，**每个都要带 `data-draft="N"`** |
| `.ocbtn` + `body.onlycur` | 「只看本稿」开关：自动出现（模块有 `meta.draft` 时），一键收掉非本稿的标注 |
| `.px-wip` / `.px-wip-bd` | 待定标注：蓝灰虚线，表示「位置留了、方案没定」。**不要用粉色假装定了** |
| `.px.tall` | 画布加高，给「弹窗本身很高」的帧用 |
| `.px.full` | **整页帧**：高度随内容长高、关掉 `.px-main` 的内部滚动。长页面一页一帧就用它 |
| `.px-dlg.wide` | 宽弹窗 1104px |
| `data-goto="<id>"` | 文内锚点：点一下切到叙事栏并滚到目标 + 高亮。**不要用 `href="#id"`**（纯原型模式下目标是 `display:none`，而且切模式会把 `pane-scroll` 归零） |
| `data-fi="<n>"` | 正文里反链回原型第 n 帧 |

**列级改动会自动整列着色**：表头写 `th.chg-col[data-chg]`，`showFrame()` 里的 `paintCols()` 会把同列 `td` 一起染上。
只标表头是不够的——缩到 40% 看时整列还是白的，等于没标。

**帧级改动条三轮扫描，少一轮就会漏**：`.pchg` 不是人工维护的清单，它扫当前帧的 `data-chg` 自动生成。

| 轮 | 扫什么 | 漏了会怎样 |
|:--|:--|:--|
| ① | `.px-chg[data-chg]` / `.px-wip[data-chg]` 块级 | 大块改动不出现 |
| ② | `th.chg-col` 里的**每个** `.chg-flag[data-chg]` | 一个 `th` 叠两个徽标时只报第一个，标签还会拼成「改⑱打款账户…」 |
| ③ | 其余任意带 `data-chg` 的元素（`td`、提示条等） | 改动落在非块级元素上时，改动条里直接消失，读者以为这一帧没改 |

③ 的标签取 `b` 加粗小标题，取不到再取冒号前的首句——**别硬切前 22 字**，会切在「一次看全 8」这种半句上。

**长页面一页一帧，不要拆成几个「页签帧」**：默认 `.px` 是 1440×≥600 的视口，内容高出就被 `.px-main` 的内部滚动吃掉，
于是有人把一页拆成三帧——但读者会以为那是三个页面，也看不出信息密度。改用 `<div class="px full">`，
画布跟着内容长高、整页一次画完。超过 3 屏（30+ 字段的超长表单）才分两段，标题写「同页 1/2」，
`from` 指**同一个页号**。详见 `references/interaction.md` 第一节。

### 原型里不写解释（硬约束 11）

线框图是**系统长什么样**，不是「为什么这么做」。之前模板里有 `.px-gnote`（说明条），结果每一帧下面都长出一段
「这一帧为什么有 8 行」「两个容易踩的点」——原型越写越像设计笔记，评审时反而看不清界面本身。

| 该写进原型的 | 该写进叙事的 |
|:--|:--|
| 按钮、标签、表头、字段值、空状态文案 | 为什么改、为什么这么设计、字段从哪来 |
| 真实存在的提示条与风险告知（两句以内） | 逐条踩坑提醒、同名不同物的辨析、给研发的叮嘱 |
| 「改㉔」这类改动徽标 | 改动的来龙去脉（`.dchg` 块） |

改动标注也因此**不能挂在说明条上**：说明条被删，标注跟着消失。标注只落界面元素（卡片块级、列级）。

界面提示条也要像产品文案：**一句主句 + 一句后果**，写长了说明放错地方（例：
「本单 1 人收款字段缺失，不影响整单提交 / 黄色＝字段没填全的提示，不代表付不出去」就够；
为什么 schema 会漂移、为什么不在发起前校验，属于正文）。

**8 段结构锁死时，附录怎么放**：`schema.py` 的 `SECTION_PLAN` 定长 8 段，不要加第 9 段。
需要独立的实现说明（如某个弹窗的变量取数），挂到某一段的末尾，标题写「附录 A」，用 `data-goto` 锚过去。

## 六、提示分级：颜色不能比约束更强

业务方两次指出同一件事：单据工作台里有人收款字段缺失，页面上要是**红色报错**，机构会以为「这单付不出去了」；
实际系统允许带着缺失提交，只是提示他补齐。**用红色表达「不阻断」，是文案与视觉对不上。**

| 档位 | 含义 | 视觉 | 组件 |
|:--|:--|:--|:--|
| **阻断** | 不解决就不能提交 | 红 `#D92D20`，实线边框，按钮置灰 | `.px-alert.danger` / `.px-fctrl.err` |
| **提示** | 能提交，但建议先补 | 琥珀 `#A9660E`、底 `#FFF6E5`、1px 虚线 | `.px-alert.warn` |
| **说明** | 只是解释，不需要动作 | 蓝灰底 `#F6F9FC` + 左竖条 | `.px-alert` / `.px-hint` |
| **禁用** | 不可选，原因见 tooltip | 灰字 `#98A2B3` + 灰底 | `.px-dislink` / `tr.dis` |

### 三条规矩

1. **颜色强度 ≤ 实际约束强度。** 能提交的页面里不许出现红色阻断样式；反过来，真正的阻断也不许用黄色糊过去。
2. **同一句话要在三处口径一致**：抽屉/页面顶部的提示条、字段悬停浮层、二次确认弹窗里的说明。
   只在一处写「不影响提交」，另两处仍是红字，读的人只会记住红色的那处。
3. **提示要有「为什么可以不管」**。只写「字段缺失」是通知；写「该网络必填字段以后台配置为准，缺了也能提交，
   打款时若被通道退回再来补」才是让人敢继续点的理由。

> 反过来说：如果一个提示你无法解释「为什么可以不管」，那它大概率是阻断，别硬做成黄色。
