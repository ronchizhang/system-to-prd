# 覆盖度：状态、场景、极限值

> 一条 PRD 的价值，不在于它把「正常情况」写得多细，而在于读的人能不能**一眼看到还会出现什么情况**。
> 这三条是被业务方当面指出来的（2026-11-02），都是「图上没画，所以研发不会做」的典型。

## 一、列表页：把状态铺开，一个状态一行

**规则**：只要模块里有列表页，就把该对象**所有状态**各画一行（能合并的合并，但不能只画一两种），
并且在**操作列**给出该状态对应的后续动作。

**为什么**：列表页是唯一能「一屏看全生命周期」的地方。只画 3 行同状态的记录，读的人看不出：

- 这张单后面会变成什么；
- 每个状态下能做什么、不能做什么；
- 哪些动作在**别的页面**（比如「待打款」的动作在单据工作台，不在本页）。

**怎么做**：

1. 状态全集从 `transitions.states` 取，不要凭印象；
2. 每个状态配一行真实感数据（编号、金额、学员数、币种都要不同）；
3. 操作列按状态给动作，**没有的动作不要画**；
4. 表下加一句「这一帧为什么有 N 行」，说明是按状态全集铺开，不是造假数据。

**反例（真实踩过）**：合作校区结算申请列表画了 3 行，全是「业务审批中」，操作列都写着「查看结算申请单 / 查看业务审批」。
读的人完全不知道这单还能走到「打款失败」，更不知道**打款失败之后没有「重新打款」按钮**——
那是与自营/合作校单据最关键的差异，图上不画就必然被抄错。

## 二、多状态 / 字段不一致：把所有可能同时出现的情况都摆出来

**规则**：一个页面里只要存在「不同状态下字段不同」「不同场景下行为不同」，就把这些分支**同时**画进 PRD，
不要只画主路径、其余用一句「其他情况类似」带过。

**判断方法**：问自己三个问题——

| 问题 | 没做到会怎样 |
|:--|:--|
| 同一张表，A 状态有这列、B 状态没有吗？ | 研发会做成一列恒显示，B 状态出现空列 |
| 同一个字段，不同协议/不同地区含义一样吗？ | 研发按一个含义实现，另一条链路全错（如 通道A 的「银行代码」是 联行号、通道E 的是 银行代码） |
| 同一条记录，可能同时有多值吗？ | 研发做成单值，多币种单直接丢数据 |

**落到图上**：多值字段画成「前 2 个 + N + 悬停列全」；多状态画成多行或并列小卡；
字段因状态而异的，就在同一帧里放两份（或用 `px-wip` 标出待定分支）。

## 三、极限值：示例数据要给极值，图里要画出超限怎么显示

**规则**：写文案 / 造示例数据时，不能只给「张三」这种正常值。每组数据里至少放**一个极值样本**，
并且在**线框图里直接把超限的显示方式画出来**。

**要覆盖的极值**：

| 类型 | 极值样本 | 图里怎么画 |
|:--|:--|:--|
| 姓名 / 账户名 | 20~30 字（含间隔号、外文名） | 单行 + 省略号，`title` 悬停显示全名 |
| 多值字段 | 4 个以上币种 / 协议 | 前 2 个 + 「+N」，悬停列全 |
| 金额 | 0、负数、超长小数 | 按实际显示，不隐藏 |
| 空值 | 字段为空 | 显示「-」，不猜、不默认 |
| 行数 | 列表满页 | 分页条要画，别只画 2 行 |

**为什么必须画出来而不是写一句规则**：研发看的是图。图里画的是换行，他就做换行；画的是省略号，他才做省略号。
规则写在正文里，实现时没人回头翻。

**技术要点（原型侧）**：

- 表格 `table-layout:fixed`，列宽固定，内容自适应；
- 长文本用 `.px-ellip`（单行截断 + `title`）；
- 需要多段内容的单元格（金额、学员名单）用 `td.wrap` 允许换行，**但那是「一条里有多段」，不是「一段太长被折断」**；
- 判据：**一页 8 行里有一行变高，整张表的扫视节奏就断了**。宁可悬停看全名，也不要让它撑高。

## 四、交付前自查清单

- [ ] 列表页是否覆盖了 `transitions.states` 的全部状态？
- [ ] 每个状态的操作列是否不同？有没有画出系统**没有**的动作？
- [ ] 多值字段是否都按「前 2 + N + 悬停」处理？
- [ ] 每个表格里是否至少有一个极值样本（超长名 / 多币种 / 空值）？
- [ ] 超限的显示方式是否**画在图上**，而不是只写在文字里？
- [ ] 不同状态 / 不同场景的分支，是否同时出现在 PRD 里？
